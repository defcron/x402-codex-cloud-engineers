- **Customer job:** Help an agent decide whether a captured HTTP response may be stored and reused, and for how long, before it adds a cache layer or replays a response.
- **Inputs:** Bounded request/response metadata only: request method and authorization/cookie presence; response status; Cache-Control, Date, Age, Expires, Vary, Set-Cookie, and optional request directives. No URL fetch, body, credentials, or payment execution.
- **Outputs:** Deterministic structured cache decision (store / do_not_store / conditional / insufficient_data), shared vs private scope, freshness lifetime when explicit metadata permits calculation, and directive-level reasons/caveats. The result is a policy interpretation, not a complete HTTP cache implementation.
- **Example:** A GET 200 with `Cache-Control: public, max-age=600`, no `Vary: *`, and no request `no-store` yields a storable response with 600 seconds of freshness; `Vary: *` or `no-store` prevents reuse.
- **Failures:** Reject malformed directives, invalid delta-seconds/date values, unsupported methods/status representations, contradictory duplicate directives where a safe result cannot be inferred, and over-limit input with bounded 4xx errors. Do not echo credential values.
- **Bounds / price target:** Header text <= 8 KiB, at most 64 directives/fields, output <= 16 KiB; pure deterministic computation, no model/API credits or network fetch; target price $0.005 USDC/request if later integrated.
