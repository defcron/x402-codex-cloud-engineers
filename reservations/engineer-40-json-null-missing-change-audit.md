# Engineer 40 reservation: JSON null/missing batch audit

- **Service key:** `json-null-missing-change-audit`
- **Owner:** Engineer 40
- **State:** CTO-assigned and recorded in the shared roster; implementation begins in this isolated branch. No deployment target or PayAPI quota is assigned.
- **Branch:** `engineer-40-json-null-missing-change-audit`, based on current `main`.
- **Customer job:** Detect changes in the distribution of absent, explicitly-null, and non-null values for selected fields across two JSON record batches. This helps an agent catch ETL/API data-contract drift where an absent property and a property set to null have different meanings.
- **Inputs:** Two non-empty arrays of JSON object records (`before_records`, `after_records`) and 1–100 caller-selected RFC 6901 JSON Pointer paths. No record identifiers, schema, network fetch, or credentials are needed.
- **Outputs:** Per path and per batch, counts and basis-point rates for `missing`, `null`, and `value`; signed count/rate deltas between batches. Values and record contents are never returned.
- **Example:** For `/email`, if 100 baseline rows contain 5 missing and 10 null values, while 100 new rows contain 25 missing and 30 null values, report +20 missing and +20 null rows, with each rate up 2,000 basis points.
- **Failures:** Reject malformed JSON values, non-object records, empty batches, invalid or duplicate pointers, and excessive records/fields/nodes/depth/input/output with bounded 4xx errors. Absent or unreachable paths count as missing.
- **Bounds / price target:** Up to 500 object records per batch, 100 pointers, 20,000 total JSON nodes, depth 32, 256 KiB serialized input, and 256 KiB output. Deterministic, no model/API calls; target integration price $0.005 USDC/request (below $0.10).
- **Live production distinctness (OpenAPI v0.8.206):** `/v1/json-diff` compares two JSON values and already reports a single field's absent-versus-null change as an add/remove with type metadata; this prototype will not repeat that pairwise behavior. It aggregates missing/null/value counts and rate deltas over selected paths across two record batches, without matching or exposing rows. `/v1/json-preflight` and `/v1/json-schema-validate-batch` validate records against a supplied contract; they do not compare cohort-level missing/null distributions. Engineer 07's `json-pointer-path-contract-check` checks selected-path presence/type, so this service stays focused on aggregate distribution changes across cohorts rather than per-record contract pass/fail.
